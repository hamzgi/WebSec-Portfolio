# 콘텐츠 데이터 모델 — 1단계

MongoDB에 저장할 콘텐츠의 형태입니다. 관리자 인증과 프로필·기술·자격증·활동 이력 편집을 구현했습니다. 현재 공개 페이지는 아직 이 모델을 조회하지 않으며 프로젝트 관리와 GitHub 동기화도 후속 단계에서 구현합니다.

| 모델 | 주요 데이터 | 비고 |
| --- | --- | --- |
| Profile | 표시 이름, 소개, 관심 분야, 이메일·소셜 링크 | `key: primary`인 단일 프로필 |
| Project | 제목, slug, 요약·상세, 기술 스택, URL, 대표 여부, GitHub 메타데이터 | GitHub 동기화 정보와 직접 작성한 설명 분리 |
| Skill | 기술 이름, 분류, 설명 | 표시 순서와 공개 상태 |
| Credential | 자격증명, 발급 기관·일자·만료일, 확인 URL | 표시 순서와 공개 상태 |
| Timeline | 활동명, 기관, 시작·종료일, 설명 | 표시 순서와 공개 상태 |
| SiteSettings | 사이트 제목·설명, GitHub 사용자명 | `key: primary`인 단일 설정 |

프로젝트·기술·자격증·활동은 기본적으로 `draft`입니다. 공개 조회를 구현할 때는 서버에서 `status: published` 조건을 적용해야 합니다. 프로필과 사이트 설정은 단일 항목이며 별도의 초안·공개 버전은 아직 구현하지 않았습니다. `sortOrder`는 숫자가 작을수록 먼저 표시하도록 후속 조회 로직에서 사용합니다.

프로젝트 slug와 GitHub repository ID, 단일 항목의 key에는 고유 인덱스를 정의했습니다. 인덱스는 실제 데이터베이스에 생성되어야 중복을 막을 수 있습니다. 관리자 콘텐츠 저장·삭제 시 서버에서 권한을 확인하고, 텍스트 길이·날짜·공개 상태·정렬값·이메일·외부 URL을 검증합니다. 외부 URL은 HTTP(S)만 허용합니다.

`lib/db.ts`는 서버 전용으로 연결을 지연 생성하고 진행 중인 연결을 재사용합니다. 연결 문자열은 `MONGODB_URI`에서만 읽습니다. 연결 실패 시 비밀값을 출력하지 않는 `npm run db:check`를 제공하며, 실제 MongoDB 연결 확인은 별도 서버와 환경 변수가 준비되어야 가능합니다.
